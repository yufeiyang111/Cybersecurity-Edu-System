# Agent Run 无权限终态设计

- 日期：2026-08-15
- 状态：已实现并完成无权限路径浏览器复验
- 范围：`/security/agent-runs/:runId` 的前端访问被拒绝（HTTP 403）体验与请求编排。

## 1. 背景与问题

真实浏览器验收中，已登录用户直接访问无权读取的 Agent Run 时，后端对 Run、计划、图谱、观察结果和审批请求均正确返回 HTTP 403。前端虽然显示了错误提示，但仍渲染任务输入框、空侧栏和“连接中”等运行态 UI，并并发发起多个必然失败的附属请求。

这会造成两类问题：

1. 用户体验错误：用户会误以为任务仍在加载或可以继续操作。
2. 请求编排错误：对无权访问的 Run 继续请求计划、图谱、观察结果、审批和 SSE，产生重复错误提示与无意义网络流量。

## 2. 目标与非目标

### 目标

- 首个主 Run 详情请求返回 403 后，任务页面进入稳定、不可交互的完整无权限终态。
- 不展示任务输入框、SSE 连接状态、计划侧栏、空数据面板、暂停/恢复/取消操作或观察结果弹窗。
- 停止 SSE，并阻止本轮后续计划、观察结果、审批、图谱、成本和覆盖率请求。
- 清空先前 Run 的状态，避免路由切换后显示旧任务数据。
- 对同一次无权访问仅保留页面内错误说明，不出现重复全局 Toast。
- 保持其他网络错误、正常 Run、会话模式和刷新行为不变。

### 非目标

- 不调整后端工作区授权逻辑；当前后端 403 行为正确。
- 不变更工作区成员关系、Feature Flag、Run 数据或数据库内容。
- 不把 404、500、断网等错误伪装为“无权限”。
- 不改变 Baseline、V2 或 Deep Review 的业务含义。

## 3. 用户体验设计

无权限终态保留安全工作台的导航与任务页顶部栏，但主工作区替换为完整错误页：

- 语义化错误状态：错误图标、标题“你没有访问此 Agent 任务的权限”、说明文本。
- 主操作：`返回 Agent 工作台`，跳转 `/security/agent`。
- 次操作：`返回项目总览`，跳转 `/security/projects`。
- 不保留刷新、暂停、恢复、取消按钮；顶栏仅保留返回入口。
- 桌面、平板与手机均在主内容区域居中显示；不渲染右侧侧栏。

## 4. 状态与请求编排

### 4.1 `useAgentRun` 的访问状态

`useAgentRun` 增加仅面向当前页面实例的 `accessDenied` 状态：

- `loadRun()` 开始时清除旧错误和旧访问拒绝状态。
- 成功时 hydrate Run、连接 SSE，并返回成功结果。
- 发生 HTTP 403 时：递增请求代次、断开 SSE、`store.reset()`、设置 `accessDenied=true`，并返回失败结果。
- 其他错误保持现有 `errorMessage` 行为，不能设置 `accessDenied`。
- `loadRun()` 返回一个可判断的加载结果，供页面决定是否继续加载附属数据。

### 4.2 `AgentChat` 的单入口加载

页面新增统一的 Run 初始化函数：

1. 先 `await loadRun(runId)`；
2. 只有加载成功且未拒绝访问时，才依次加载计划版本、观察结果、审批、图谱等附属数据；
3. `onMounted`、路由 `watch`、刷新和会话 Turn 跳转均复用该函数；
4. 所有会在终态后触发的 watcher 均检查 `accessDenied` 后短路；
5. 无权限状态不连接、或立即断开 SSE。

这样可以消除真实验收中同一页面产生的多次 403。

### 4.3 错误提示去重

请求层支持对特定、已由页面完整呈现的请求关闭通用 Toast。`getRun()` 的 403 由页面错误态呈现；其他场景仍保留当前统一 API 错误提示策略。

## 5. 组件与文件边界

预计改动：

- `frontend/src/composables/security/useAgentRun.js`
  - Run 主请求的权限拒绝识别、状态重置、SSE 停止和加载结果。
- `frontend/src/views/security/AgentChat.vue`
  - Run 单入口加载编排、模板门禁与响应式完整错误页。
- `frontend/src/api/index.js`
  - 为 Run 主详情请求提供受控的“由页面处理错误”配置，避免重复 Toast。
- `frontend/src/features/security/agent/` 下新增一个小型纯函数模块（仅在现有测试难以直接验证 HTTP 403 判定时使用）。
- `frontend/tests/agent-*.test.mjs`
  - 覆盖 403 判定、非 403 不误判、禁止附属请求的决策逻辑。

不新增依赖，不修改后端和数据库。

## 6. 验收标准

### 自动化

- 403 被识别为访问拒绝；401、404、429、500、网络异常不被误判。
- Run 主请求被拒绝后，辅助加载决策返回 false。
- 正常 Run 允许辅助加载；普通错误维持现有错误提示路径。
- 既有 `npm --prefix frontend run test:agent` 全部通过。
- `npm --prefix frontend run build` 通过。

### 真实浏览器

以无权限用户访问真实存在但不属于其工作区的 `/security/agent-runs/:runId`：

- 只看到完整无权限错误页与两个返回操作；
- 不显示“连接中”、输入框、计划、观察结果、审批、图谱或任务控制按钮；
- Network 中仅允许 Run 主详情的 403；不得产生计划、观察结果、审批、图谱和 SSE 请求；
- 返回 Agent 工作台后页面正常展示；
- 正常有权限 Run 不受影响（如存在可安全访问的测试数据时补验）。

## 7. 风险与回滚

- 风险：统一加载顺序由并行转为“主 Run 成功后再加载附属数据”，正常页首屏附属数据可能延后一个网络往返。
- 取舍：优先保证权限错误时没有伪运行态和无意义请求；主 Run 详情是所有附属数据的授权与状态前提。
- 回滚：前端可独立回滚；不涉及数据库迁移和后端契约变更。
## 8. 实施结果（2026-08-15）

- 403 由 `useAgentRun` 识别为稳定访问拒绝状态：停止 SSE、清空 Run Store，并阻止附属数据加载。
- `AgentChat` 在主 Run 未完成授权校验前只展示骨架屏；校验成功后才挂载任务布局及其附属组件。
- 无权限时仅显示完整错误页、返回 Agent 工作台和返回项目总览操作；不显示运行控制、输入框、计划侧栏或“连接中”。
- 真实浏览器复验确认：页面仅发起主 Run 的 403 请求；未再发起 plans、observations、approvals、graph 或 SSE 请求。
- 自动化验证：`npm --prefix frontend run test:agent` 通过（52 项）；`npm --prefix frontend run build` 通过。
